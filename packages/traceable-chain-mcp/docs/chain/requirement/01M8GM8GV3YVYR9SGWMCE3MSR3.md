## 背景

リンクを強制するだけでは、上位が書き換わっても下位は何も言われない。実装やコードが変わっても、設計・仕様・要求が満たされ続けているかを誰も確かめない。

## 要求

1. 上位の文書が変わったら、それに従う下位の文書を「要再確認」にする。
2. 下位の文書が変わったら、それが上位を満たし続けているかを「要再確認」にする。
3. コードが変わったら、それを実現している implementation から始めて、最上位まで遡る道筋を示す。
4. 解消は上位から。上位が未解決のうちは下位を確定できない。
5. CI や pre-commit から機械的に止められること。
