# db-read-mcp

Read-only relational DB access exposed as MCP tools, driven by user-supplied
`metadata.json` + `selectable-fields.json` (typically generated by
[`db-codegen-mcp`](../db-codegen-mcp)).

Supported engines:

- PostgreSQL (`postgres://` / `postgresql://`) — via [`mcp-shared-db-postgres`](../mcp-shared-db-postgres)
- MySQL (`mysql://`) — via [`mcp-shared-db-mysql`](../mcp-shared-db-mysql)

Supported tunnels (optional, mutually exclusive):

- SSH bastion (`*_BASTION_HOST`)
- AWS SSM port forward (`*_SSM_TARGET`) — internal session managed by the MCP

When neither is configured, the MCP connects directly to the URL host.

## Setup

### 1. env file

```env
# Database URL — points at the **logical destination** of the connection.
# When a tunnel is configured (below) this is the remote endpoint the
# tunnel forwards to, not the local proxy port.
DBREAD_URL=mysql://USER:PASS@db.example.internal:3306/appdb

# Optional: bound query runtime. PG duration form ("5s" / "500ms" / "0").
# Default: 10s.
DBREAD_STATEMENT_TIMEOUT=10s
```

#### Alternative: per-component env vars

If the connection parts live in SSM (or Secrets Manager) as separate
parameters — common when AWS RDS metadata is published piece-by-piece —
set the components individually instead of pre-baking a URL. All six
required parts must be present to opt in; otherwise `DBREAD_URL` is
used as a fallback. If both are set, parts win and the MCP logs a
stderr warning so it isn't silent.

```env
DBREAD_DIALECT=postgres            # or "mysql"
DBREAD_HOST=ssm:/myapp/db/host
DBREAD_PORT=ssm:/myapp/db/port
DBREAD_USER=ssm:/myapp/db/user
DBREAD_PASSWORD=ssm:/myapp/db/password
DBREAD_DATABASE=ssm:/myapp/db/name
DBREAD_PARAMS=sslmode=require      # optional extra query string;
                                   # leading `?` is trimmed if present
```

`USER` / `PASSWORD` / `DATABASE` go through `encodeURIComponent`, so
special characters in the password (`@` `:` `/` `?` `#`) don't need to
be hand-escaped in SSM.

#### Tunnel: AWS SSM port forward (recommended for VPC-private RDS)

```env
DBREAD_SSM_TARGET=i-0123abcdef           # EC2 instance with SSM agent
DBREAD_SSM_REGION=ap-northeast-1         # optional — falls back to AWS_REGION
DBREAD_SSM_PROFILE=my-profile            # optional — falls back to AWS_PROFILE
DBREAD_SSM_DOCUMENT_NAME=...             # optional — default
                                         #   AWS-StartPortForwardingSessionToRemoteHost
DBREAD_SSM_READY_TIMEOUT_MS=15000        # optional — extend cold-start budget
```

The MCP spawns `aws ssm start-session` itself, allocates a free local port,
forwards the URL's host:port through it, rewrites the URL to
`127.0.0.1:<auto>`, then connects. The session is killed (SIGINT → SIGKILL
fallback) when the MCP shuts down.

Requirements on the host:

- `aws` CLI on PATH.
- [`session-manager-plugin`](https://docs.aws.amazon.com/systems-manager/latest/userguide/install-plugin-verify.html)
  on PATH (the aws CLI shells out to it for port forwarding).
- IAM principal with `ssm:StartSession` on the target instance.

#### Tunnel: SSH bastion (legacy)

```env
DBREAD_BASTION_HOST=ec2-user@bastion.example
DBREAD_BASTION_KEY=~/.ssh/key.pem        # optional
DBREAD_BASTION_EXTRA_ARGS=               # optional, space-separated ssh -o flags
```

`DBREAD_BASTION_HOST` and `DBREAD_SSM_TARGET` are mutually exclusive — set
one, not both. If both are present the MCP throws on startup.

#### Migration from external SSM port forward

If you previously ran `aws ssm start-session ... --localPortNumber=13306`
externally and pointed `DBREAD_URL` at `localhost:13306`, switching to the
internal SSM mode requires:

1. Replace the URL host:port with the **real remote endpoint** (e.g. RDS
   hostname:3306).
2. Add `DBREAD_SSM_TARGET` (and optionally region / profile).
3. Stop running the external `aws ssm start-session` — the MCP manages the
   session now.

The URL semantically shifts from "literal local proxy" to "logical remote
destination" — the env key stays the same but the value changes meaning.

### 2. `.mcp.json` entry

```json
{
  "mcpServers": {
    "db-read-mcp-myapp": {
      "command": "sh",
      "args": [
        "-c",
        "cd /path/to/mcp-servers && exec npx tsx ./packages/db-read-mcp/src/index.ts --env-file /path/to/myapp.env --metadata /path/to/metadata.json --selectable-fields /path/to/selectable-fields.json --tool-prefix myapp"
      ]
    }
  }
}
```

Generate `metadata.json` / `selectable-fields.json` with
[`db-codegen-mcp`](../db-codegen-mcp).

### `selectable-fields.json` visibility policy

Each field carries a `select` policy controlling how the read tools
expose its value:

| `select` | Query | Output |
|---|---|---|
| `"expose"` | accepted | value returned as-is |
| `"redact"` (default) | accepted | value replaced with `[REDACTED]` |
| `"exclude"` | rejected | column never reaches the caller |

```json
{
  "users": {
    "fields": {
      "id":    { "select": "expose" },
      "name":  { "select": "redact", "note": "real name" },
      "ssn":   { "select": "exclude" }
    }
  }
}
```

**Secure-by-default**: a field with no `select` is treated as `"redact"`.
`db-codegen-mcp`'s `preview_selectable_fields_json` emits every generated
field as `{ "select": "redact" }` — the operator opts each field into
`"expose"` after audit, or `"exclude"` for columns that should never
appear in query results.

**Legacy `{ "pii": true, "piiReason": "..." }`** is still accepted (read
as `select: "redact"`). On startup, db-read-mcp prints a one-shot
migration nudge listing every legacy site so operators can convert at
their own pace.

## Tools

The MCP registers two tools (prefix configurable via `--tool-prefix`):

- `<prefix>_describe` — list / inspect available read operations
- `<prefix>_execute` — execute one operation

Operations are read-only by design (the underlying SQL builder rejects
non-SELECT shapes; the session is also `default_transaction_read_only = on`
on PG / `transaction_read_only = 1` on MySQL as belt-and-braces).

Read operations include:

- `list_tables` / `list_table_fields` — schema discovery
- `get_by_pk` / `get_by_fk` / `get_by_index` — keyed lookups
- `get_by_date_range` — bounded range scans (with auto-EXPLAIN guard)
- `json_search` — JSON-path equality (`#>>` on PG, `JSON_EXTRACT` on MySQL)
- `explain_sql` — ad-hoc EXPLAIN for sizing

Use `<prefix>_describe` to see the full list and per-op argument schemas.

## Troubleshooting

**`session-manager-plugin not found`**: install per AWS docs. The aws CLI
prints the install URL itself when the plugin is missing — that's the
clearest signal.

**Cold-start timeout**: SSM session establishment can take 5–15s.
`DBREAD_SSM_READY_TIMEOUT_MS` extends the budget when the default 15s
isn't enough.

**`Set at most one of *_BASTION_HOST or *_SSM_TARGET`**: env has both —
remove one.

**`ECONNREFUSED 127.0.0.1:<port>`**: tunnel didn't bind. Usually means the
SSM session ended early (auth failure, plugin missing). Check stderr for
the `[ssm-tunnel]` prefix lines forwarded from the aws CLI.

**TLS warning despite tunnel**: only fires when no tunnel is configured.
If you see it with tunnel set, the env keys aren't being read (typo /
prefix mismatch).
