[[dependencies]]
== 依存

矢印は「使う」向き。サーバーの側は bundle に埋め込むため `+devDependencies+` に書いてあるものも含む。テストのためだけの依存 (`+mcp-firewall+` → `+git-repo-explorer-mcp+` など) と、推移的に辿れる矢印 (`+db-read-mcp+` → `+mcp-shared+` など、DB 系はどれも最後は `+mcp-shared+` を使う) は省いた。

[plantuml]
----
@startuml
skinparam componentStyle rectangle

package "mcp-shared だけを使うサーバー" as only {
  component "interactive-pdca-mcp" as pdca
  component "traceable-chain-mcp" as chain
  component "ast-file-mcp" as astf
  component "ast-typescript-mcp" as astt
  component "git-repo-explorer-mcp" as git
  component "kroki-mcp" as kroki
  component "duckdb-mcp" as duck
  component "mcp-lab" as lab
}
component "interactive-instruction-mcp" as iim
component "db-read-mcp" as dbr
component "db-codegen-mcp" as dbg

component "mcp-shared-graph-viz" as viz
component "mcp-shared-secrets" as sec
package "DB 系のライブラリ" {
  component "mcp-shared-db-postgres" as pg
  component "mcp-shared-db-mysql" as my
  component "mcp-shared-db-sql" as sql
  component "mcp-shared-db" as db
  component "mcp-shared-db-codegen" as cg
  component "mcp-shared-dynamodb" as ddb
  component "mcp-shared-db-core" as core
}
component "mcp-shared" as shared

only --> shared
iim --> shared
iim --> viz
dbr --> pg
dbr --> my
dbr --> db
dbr --> sec
dbg --> cg
dbg --> sec
pg --> sql
my --> sql
sql --> db
db --> core
cg --> core
ddb --> core
core --> shared
@enduml
----

`+mcp-firewall+`、`+cli-to-mcp+`、`+graph-math-mcp+`、`+python-diagrams-mcp+`、`+mcp-shared-secrets+` は他のパッケージに依存しない (`+mcp-shared-secrets+` は npm の依存も 0。AWS は `+aws+` CLI を呼ぶ)。

[[bundle]]
== bundle と依存

`+mcp-shared*+` は npm に出さないので、それに依存する package.json のまま公開すると、誰も install できないパッケージになる。そこで公開しうるサーバーは tsup で `+mcp-shared*+` を `+dist/index.js+` に埋め込み、`+mcp-shared*+` は `+devDependencies+` に置く (共通の設定は `+scripts/tsup-bin-config.ts+`)。

[plantuml]
----
@startuml
left to right direction
rectangle "packages/kroki-mcp/src/*.ts" as src
rectangle "packages/mcp-shared/src/*.ts" as shared
rectangle "tsup\n(noExternal: /^mcp-shared/)" as tsup
rectangle "dist/index.js\n(mcp-shared を含む)" as dist
rectangle "scripts/verify-bundle.mjs" as verify
rectangle "npm の package\n(dependencies は外部のものだけ)" as npm

src --> tsup
shared --> tsup
tsup --> dist
dist --> verify : esbuild の metafile で\n残った import を調べる
verify --> npm : 宣言していない import が\n無ければ公開できる
@enduml
----

* `+dependencies+` に書いたもの (zod、`+@modelcontextprotocol/sdk+` など) は外部のまま残し、利用側で重複を除けるようにする。
* `+node-notifier+` は CommonJS で、ESM の bundle に入れると起動時に `+Dynamic require of "os" is not supported+` で落ちる。なので external にして、使わない bin では tree-shake で消えるようにしている。
* `+scripts/verify-bundle.mjs+` は、`+dist/+` に残った bare import が node の組み込みか宣言済みの依存であることを確かめる。テキストの検索ではなく esbuild の metafile を読む (ツールの説明文の中の `+from "x"+` を import と間違えないため)。
* `+interactive-pdca-mcp+` と `+traceable-chain-mcp+` はまだ `+mcp-shared+` を `+dependencies+` に持つ (tsup にしていない)。GitHub Packages への公開 (`+gpr-release.yml+`) はこの形を拒む。
