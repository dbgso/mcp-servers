## 実装中に設計を修正した点

### 1. `boundingBox` を常に渡すのは間違いだった

設計段階では「breadthfirst が壊れるので boundingBox を**常に**明示指定する」としていた。これを実装して実データを描画したところ、**ノードが重なった**。

原因: cytoscape はレイアウト結果を `boundingBox` に**リスケール**する。dagre が計算した適切な間隔が、固定サイズの箱への引き伸ばしで上書きされていた。

証拠（孤立ノード 6 件 + a→b、dagre LR）:

| | y 座標 | 判定 |
|---|---|---|
| 修正前 | 0, 133, 267, 400, 533, 667, 800 | 800 を正確に 6 等分 = 箱へのリスケール。高さ 56 のノードが重なる |
| 修正後 | 19, 106, 193, 280, 367, 454, 541 | 87px 間隔 = nodeSep が生きている。重なりなし |

修正: `boundingBox` は**面積ベースのレイアウトのみ**（grid / circle / concentric / breadthfirst）に渡す。dagre / cose / preset には渡さない。

さらに、面積ベースレイアウトに渡す箱も固定 1200x800 をやめ、ノードの総面積から算出する（`estimateBoundingBox`）。固定値だと 3 ノードのグラフが 1200x800 に引き伸ばされ、大きなグラフは押し込められるため。

### 2. headless では要素の `position` が無視される

`preset` レイアウトのテストで発覚。要素定義に `position: {x:42,y:24}` を与えても、headless では `(0,0)` になる（検証済み: `before layout: { x: 0, y: 0 }`）。`positions` オプションでレイアウトに直接渡すと正しく反映される。

修正: `buildPresetPositions` で座標をレイアウトに明示で渡す。座標を持たないノードがある状態で `preset` を選んだ場合は、全員が原点に重なるのを黙認するより `GraphVizError` で落とす。

### 3. 逆方向の平行エッジが重なっていた

A→B と B→A が両方とも同じ側に曲がっていた。オフセットをエッジ自身の向きに対して適用していたため、向きが逆になると法線も反転して相殺していた。

修正: ノード対の正規順（id ソート順）に対して符号を揃える。

### 4. 行数上限で切られたラベルに省略記号が付かないケース

最終行がそれ単体では幅に収まる場合、切り捨てた行があるのに `…` が付かなかった。`truncateToWidth`（収まるならそのまま）を `elideToWidth`（常に `…` で終わる）に入れ替えた。
