# AI の報告を、事前定義した構造から HTML として配送する

## 背景

AI からの報告が読みにくい。issue #84 のセッションでは、同じ内容を4回説明し直した。

通じたのは、`npm pack` の出力をそのまま貼ったときだけだった。

```
dist/      176 ファイル
templates/   5 ファイル
README.md
LICENSE
docs/ 由来:  0 ファイル
```

通じなかった4回は、すべて AI が結論を自分の言葉で言い換えた箇所だった。

報告のたびにフォーマットを決めるのは手間がかかる。資料を毎回作るのも手間がかかる。

ユーザーの言葉（原文）:

> 事前に定義した構造にあなたがインプットしたら勝手にそれが出来上がる形です。
>
> 毎回報告フォーマットを定義するのは大変で、毎回生成するのも大変です。それを賄うためのツールです。

## 要求

### 1. ゲートではない

ユーザーが「このツールで報告して」と言ったときに AI が使う。

AI の最終メッセージを検閲する仕組みにはしない。

### 2. AI は構造化された値だけを渡す

AI は散文も HTML も組み立てない。

事前に定義したテンプレートの項目を埋めるだけにする。

### 3. 必須項目が欠けた報告は受け付けない

強制力は入力の検証から来る。

欠けている項目があれば、どれが欠けているかを全件返して差し戻す。

### 4. 出力は人間が開く HTML ファイル

人間は HTML ファイルを開いて報告を読む。

フォーマットを都度決める必要も、資料を都度作る必要もなくなる。

## 受け入れ条件

- 「このツールで報告して」と言われた AI が、ツールを1回呼ぶだけで HTML ファイルが得られる
- AI が HTML・CSS・散文の段落を書かなくてよい
- 必須項目が1つでも欠けた入力では HTML が生成されず、欠けた項目名がすべて返る
- ツールは AI の最終メッセージを読まない。呼ばれなければ何もしない

## この要求に含めないこと

- **報告の項目そのもの。** 何を必須にするかはユーザーが決める。spec で扱う。
  issue #84 のコメントにある v1 案（`conclusion` / `claims[]` など）は AI の起案であり、合意されていない。
- **chain への登録。** 受けた報告から chain に設計書を起こす構想はあるが、別の要求とする。
- **iimcp・chain との役割整理。** 被りは認識しているが、一旦は本ツールに集中する。
